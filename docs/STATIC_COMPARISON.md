# Сравнение со статическим режимом

Если на alpha.17 страница YouTube открывается, а видео не воспроизводится,
можно сравнить новый автоматический контроллер с прямым применением уже
сохранённых стратегий. Это временная диагностика на роутере, а не подтверждённое
исправление видео и не завершение разработки полного автоподбора.

Из SSH Entware от root:

```sh
curl -fsSL https://raw.githubusercontent.com/punisher89/my.kn-test-/refs/heads/feature/keenetic-pilot/scripts/test-static-mode.sh -o /tmp/pilot-static-test.sh && sh /tmp/pilot-static-test.sh
```

Скрипт сохраняет исходный config.json в приватный
`/opt/etc/keenetic-pilot/config.before-static-test.json`, выключает `adaptive`
и `auto`, проверяет кандидата штатным `--check-config` и перезапускает свою
службу. Стратегии профилей, домены, пароль, ключи, наблюдения и подтверждённые
методы сохраняются. В режиме сравнения полный поиск не работает; используются
сохранённые стратегии и обычные правила статического режима. Это сравнение
путей обработки целиком, не доказательство конкретной ошибки в Lua.

После команды перезапустите браузер, чтобы установить новые соединения,
и проверьте тот же ролик. Результат помогает выбрать следующий шаг: искать
регрессию автоматического пути или проверять сохранённый метод и сетевой путь.
До восстановления не меняйте другие настройки Pilot: восстановление возвращает
точную исходную конфигурацию.

Вернуть настройки:

```sh
sh /tmp/pilot-static-test.sh --restore
```

При неудачном старте скрипт возвращает конфигурацию, действовавшую до команды,
и пытается запустить прежнюю службу. Повторный вход в тест запрещён до
восстановления, чтобы исходная копия не перезаписалась. Локально проверены
сохранность параметров/ключа доступа, точное восстановление файла и откат
после отказа запуска. Воспроизведение видео на роутере этим прогоном не проверяется.
