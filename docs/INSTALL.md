# Установка alpha на Keenetic

Первый стенд — KN-1811 с Entware на USB. Работа сетевого обхода на нём пока
не подтверждена. Подготовлены собственный установщик, управление службой и
восстановление правил; сначала нужны испытания.

## Предпосылки

1. KeeneticOS с установленными компонентами OPKG / Entware и Netfilter.
2. Entware доступен в `/opt`, вход в его shell от root.
3. Доступ к GitHub Releases и репозиториям Entware для загрузки зависимостей.
4. z2k/D2K и другие обработчики того же трафика должны быть остановлены перед
   испытанием. Pilot не останавливает, не удаляет и не перенастраивает их.

## Получить пакет

Пакеты собираются нашим CI в GitHub Actions → `Build and validate Keenetic Pilot`
→ артефакт `keenetic-pilot-alpha-packages`. Смотрите результат конкретного запуска;
наличие workflow в Git само по себе не означает успешной сборки в Actions.
Пакеты также можно собрать на ПК:

```sh
ARCHES=arm64 sh scripts/build.sh
```

Для KN-1811 сначала сверьте `uname -m` с архитектурой пакета; ожидается aarch64.
Скопируйте архив и `SHA256SUMS` из `dist/` на USB. Установщик не требует Go,
Python или Node на роутере.

## Проверить и установить

В каталоге с архивом и `SHA256SUMS` проверьте именно скачанный файл:

```sh
grep 'keenetic-pilot-0.1.0-alpha.1-linux-arm64.tar.gz$' SHA256SUMS | sha256sum -c -
tar -xzf keenetic-pilot-0.1.0-alpha.1-linux-arm64.tar.gz
cd keenetic-pilot
ip route get 1.1.1.1
```

Последняя команда только показывает выбранный маршрут. В следующем примере
**замените `ppp0` на интерфейс из своей конфигурации**, а `192.168.1.1` — на
реальный LAN-адрес роутера:

```sh
sh scripts/install.sh --wan ppp0 --listen 192.168.1.1:9080
```

Установщик проверяет файлы пакета, устанавливает зависимости Entware,
скачивает закреплённый выпуск nfqws2 с обязательной проверкой SHA-256 и
проверяет его параметры/Lua до изменения работающей установки. Он не исполняет
скрипты из архива движка. Если пакеты уже установлены, можно передать
`--skip-packages`; это не отключает проверку контрольных сумм или TLS.

Панель слушает конкретный LAN-адрес. Откройте его в браузере на порту `9080`.
Ключ входа сохранён в `/opt/etc/keenetic-pilot/access-token` с правами `0600`.
Просмотреть его нужно локально по SSH; не публикуйте ключ или файл в чате/Git.

По умолчанию **запускается контроллер, а обход остаётся выключен**. Проверьте
WAN, протоколы и профили, затем включите обход через панель. TLS-проверки
используют доверенные сертификаты Entware; ошибки сертификатов не игнорируются.

Для панели только через SSH-туннель можно оставить адрес `127.0.0.1:9080`
(не указывать `--listen`). LAN-режим использует HTTP; для защиты ключа на
недоверенной локальной сети используйте SSH-туннель или локальный HTTPS-прокси.

## Управление

```sh
/opt/etc/init.d/S98keenetic-pilot status
/opt/etc/init.d/S98keenetic-pilot restart
/opt/etc/init.d/S98keenetic-pilot stop
/opt/keenetic-pilot/bin/pilot --doctor
/opt/keenetic-pilot/bin/pilot --check-engine
/opt/keenetic-pilot/bin/pilot --health
```

`status`/`health` показывают состояние контроллера и движка раздельно.
`--doctor` делает диагностику без установки правил; успешный dry-run проверяет
параметры и Lua, но не подтверждает прохождение трафика.

NDM-хук `/opt/etc/ndm/netfilter.d/095-keenetic-pilot.sh` запрашивает восстановление
через приватный Unix-сокет. Контроллер дополнительно проверяет процесс и правила
каждые 30 секунд. Правила содержат метку `keenetic-pilot` и `--queue-bypass`,
чтобы отсутствие потребителя очереди не обрывало соединения.

## Обновление и откат

Распакуйте и проверьте новый пакет, повторите `scripts/install.sh`. Сохраняются
конфигурация, ключ и результаты. Загрузка и проверка нового движка завершаются
до остановки старой службы. При ошибке после замены файлов установщик пытается
вернуть прежнюю установку и её службу; ошибка отката не скрывается.

Предыдущие файлы сохраняются в `/opt/keenetic-pilot.backup.<timestamp>.<pid>`.
Это резерв приложения; настройки находятся отдельно. Для ручного возврата
версии предпочтительна повторная установка соответствующего проверенного пакета.
Резервные копии автоматически не удаляются — следите за местом на USB.

При ошибке старта сначала смотрите `/opt/var/log/keenetic-pilot.log`, затем
диагностику панели. Не удаляйте `firewall.json`: он нужен для очистки собственных
правил и восстановления исходных sysctl после аварийного завершения.

## Удаление

```sh
sh /opt/keenetic-pilot/scripts/uninstall.sh
```

Удаляются наше приложение, init-скрипт и хук. Конфигурация, ключ, отчёты,
журнал и резервные копии сохраняются. Пакеты Entware и файлы других проектов
не удаляются. При незавершённой очистке правил удаление останавливается,
чтобы не потерять журнал восстановления.

## Проверка именно вашего сценария

- На ПК и телефоне: вход в YouTube, запуск и перемотка нескольких видео.
- На webOS: запуск приложения YouTube, ролики и перемотка. Тест TLS 1.2
  в панели не воспроизводит ClientHello телевизора и не доказывает работу видео.
- Discord: вход, сообщения, вложения; отдельно голосовой звонок. HTTPS-тест
  не подтверждает голос; UDP-профиль пока экспериментальный.
- После переподключения WAN и перезагрузки: повторить проверки и статус.
- IPv6 включать в панели только при работающем IPv6 у провайдера; обе семьи
  тогда проверяются независимо. QUIC пока использует статическую стратегию.

Для дальнейшей диагностики полезны модель, версия KeeneticOS, архитектура,
результаты этих проверок и отчёт `--doctor`. Не присылайте ключ доступа.
