# Публикация alpha.18 из Windows

Этот файл описывает выпуск **для меню «Обновления»**, а не установку через SSH.
Пакеты `alpha.18` собираются на GitHub Actions, Linux на ПК не нужен.

**Обязательное условие**: нужен ОРИГИНАЛЬНЫЙ закрытый ключ
`updates-signing.pem`, которым был подписан предыдущий выпуск.
`internal/pilot/updates-public.key` — публичная половина для проверки,
не годится для подписания. Ключ намеренно не хранится в Git и не доступен
другим людям. Если приватная половина потеряна, обновление из
**уже установленной alpha.17** не будет доверять новому ключу; без
одноразовой миграции/переустановки это исправить нельзя.

## Минимум действий на Windows

1. Найдите на своём ПК **оригинальный** файл `updates-signing.pem`.
   Если файла нет, проверьте исходную локальную рабочую копию Codex и её
   резервные копии. Ключ нельзя вычислить по `updates-public.key`.
2. Установите официальный GitHub CLI (`gh`) на Windows, если его ещё нет:
   `winget install --id GitHub.cli -e`. В новом PowerShell войдите в
   GitHub: `gh auth login`.
3. Из папки репозитория запустите локальный PowerShell-скрипт:
   `powershell -NoProfile -File scripts/publish-alpha18-windows.ps1 -KeyPath "C:\\путь\\к\\updates-signing.pem"`.
   Либо скачайте скрипт из GitHub и запустите с его абсолютным путём.
4. Скрипт проверит, что `publish-alpha18.yml` ссылается на **точно
   последний коммит**, передаст оригинальный PEM прямо в защищённый
   GitHub Actions Secret (через stdin `gh secret set`) и перезапустит
   соответствующий проваленный release run. Он не выводит ключ в консоль,
   не пишет его в Git и не передаёт в ChatGPT.
5. В GitHub Actions убедитесь, что release run **Success** и
   `packages/latest.json` указывает на `0.2.0-alpha.18`, затем откройте
   **«Обновления» → «Проверить версию» → «Установить»** в панели Pilot.

Публикация защищена исходным публичным ключом Ed25519 и проверяет SHA-256
пакетов. Сценарий отказывается публиковать выпуск, если ключ не соответствует
`internal/pilot/updates-public.key`. Не создавайте новый ключ, не удаляйте
проверку подписи и не устанавливайте неподписанные архивы на роутер.

**Важно**: `alpha.18` тестовая версия, исправления YouTube и Telegram
нужно отдельно проверить на настоящем Keenetic. Перед проверкой сохраняйте
рабочую конфигурацию, избегайте одновременного изменения других сервисов.
