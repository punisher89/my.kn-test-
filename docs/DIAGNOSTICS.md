# Диагностика автоподбора

Начиная с `0.2.0-alpha.7`, откройте **Коробки обхода → Скачать диагностику**.
Браузер сохранит `keenetic-pilot-diagnostics-<время>.json`. Поиск и фильтры
не ограничивают отчёт. Ничего вводить в SSH и перезапускать не требуется.

В файл входят версия Pilot, архитектура, режим и состояние службы, параметры
автоподбора, домены профилей, идентификаторы методов и их семейства, ручные
закрепления, паузы, исключения, текущие наблюдения, сохранённая история и
проверки двух файлов обучения. `schema_version` обозначает формат отчёта.

Файл содержит домены, имя WAN-интерфейса и времена соединений — он не анонимный.
Пароли, API/GitHub-токены, коды сопряжения, cookie, имена файлов, журналы,
контрольные URL, результаты активных проб и свободный текст ошибок не выгружаются.
Ошибки службы и чтения наблюдений отмечены флагами `has_error` и
`observation_read_error`; их текст остаётся в локальной панели/журнале.
Отчёт собирается по явному списку полей, а не путём очистки всей конфигурации.
Никуда автоматически файл не отправляется.

## Как читать наблюдения

- `current` — все сохранённые записи доменов. `group` различает группы движка;
  после смены профиля возможны несколько записей одного домена/контекста.
  Сравнивайте `updated`: карточки панели используют новейшую запись для
  сочетания домена, TLS, IP, WAN и порта.
- `observed_strategy` и `observed_status` — сохранённые метод и результат.
  Метод `none` означает «Без вмешательства», а не отсутствие назначения.
  `observed_strategy_known: false` означает, что идентификатор отсутствует в
  текущем наборе встроенных и загруженных методов.
- `pinned` и `paused` — действующие ручные переопределения; они не переписывают
  старый результат. `pinned_pending` означает отсутствие наблюдения для
  закреплённого метода, если записан другой метод.
- `tls`, `family`, `network`, `port`, `symptom` — контекст наблюдения;
  `box` — идентификатор соответствующей коробки. `origin` показывает источник
  метода: начальный, общий набор, опыт, восстановление или ручной выбор.
- `history` — сохранённые события. Их причины относятся к моменту события,
  даже если сейчас метод, закрепление или состояние службы уже изменились.

`reason` помогает отличить текущие причины ожидания:

| Код | Значение |
| --- | --- |
| `probing`, `selected` | Метод пробуется или выбран для следующих соединений |
| `connected` | Наблюдалась передача данных |
| `cooldown` | Пауза между сменами |
| `limit` | Лимит смен за десять минут |
| `paused` | Действует исключение или ручная пауза |
| `pinned` | Метод закреплён; результат смотрите в `observed_status` |
| `pinned_pending` | Для нового закрепления ещё нет наблюдения |
| `service_stopped` | Движок сейчас не запущен; данные сохранены ранее |
| `adaptive_disabled` | Автоподбор сейчас выключен |
| `failed` | Историческое событие неудачи метода |

Времена наблюдений и лимитов — Unix seconds; `generated_at` — время UTC в ISO 8601.
`recorded_hold_until` и `recorded_hold_reason` сохраняют записанное ограничение,
которое могло уже истечь или уступить ручному правилу. Для действующего состояния
используйте `reason`. Окончание паузы само по себе не запускает новую смену:
для продолжения нужны новые сбои соединений.

## Файлы обучения и границы отчёта

`storage` проверяет два слота сохранения. `valid` — завершённый корректный кадр;
`missing` — файл отсутствует; `unreadable` — файл невозможно прочитать;
`invalid_or_incomplete` — содержимое не прошло проверку, в том числе пустой
новый файл. Один некорректный слот не означает потерю всего опыта: Pilot
использует новейший завершённый корректный кадр. `generation` показывает
загруженное поколение; ноль означает, что сохранённый кадр не был выбран.

Служба не останавливается на время экспорта. Наблюдения и проверки файлов
могут попасть на разные моменты записи; снимок не является транзакционным.
Сохраняются до 512 записей и 128 событий, а не вся история сетевого трафика.

Выгрузка не запускает сетевые проверки, не читает правила firewall и не
подтверждает работу NFQUEUE на устройстве. `connected` не подтверждает
содержимое HTTPS, видео YouTube или голос Discord. В демонстрационном макете
скачивается пример с `sample: true` и режимом `mockup`; это не данные роутера.

API для авторизованных клиентов: `GET /api/diagnostics`. Действуют обычные
проверки сеанса/Bearer-ключа и Origin; ответ имеет `Cache-Control: no-store`.
