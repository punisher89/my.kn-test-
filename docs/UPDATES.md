# Обновление Pilot из меню

С `0.2.0-alpha.10` откройте **Обновления → Проверить версию → Установить**.
Чтобы получить само меню на старой версии, сначала один раз выполните прежнюю
установочную SSH-команду. Пункт обновляет Pilot, панель, Lua-контроллер и
закреплённый nfqws2 как согласованный пакет; это не обновление KeeneticOS.
Каталог подписанных стратегий можно загрузить отдельно той же страницей.

Меню установки работает для управляемой службы с маркером Pilot, штатными
путями относительно своего префикса, init-скриптом и PID-файлом текущего
контроллера. В `/opt` нужен root. Режим разработки показывает сведения о
версиях, но не запускает установку. Для локальных тестов поддерживается свой
префикс; системные пакеты и правила реального роутера в таких тестах не меняются.

Проверки и порядок:

1. Получить `packages/latest.json` и подпись, проверить отдельным Ed25519-ключом.
2. Предложить только более новый выпуск `X.Y.Z-alpha.N`. Установить можно только
   версию из проверенных сведений; произвольные URL и команды не принимаются.
3. Проверить SHA-256 манифеста и выбранного архива для своей архитектуры.
4. Распаковать в приватный каталог, запретив обход путей, ссылки и специальные
   файлы; ограничить размер и число файлов. Проверить PLATFORM, VERSION,
   закрепление движка и версию нового бинарника.
5. Проверить чтение текущей конфигурации новым бинарником.
6. Запустить отдельный процесс установщика. Он проверит внутренний манифест,
   скачает и проверит закреплённый движок, проверит nfqws2/Lua до остановки
   действующей службы. При ошибке применения сработает прежний откат установщика.
7. Проверить версию установленного бинарника и записать итог операции.

Установщик сохраняет настройки, пароль, ключи, списки, обучение, отчёты и
резервную копию предыдущего приложения. Он перезапускает службу, поэтому
соединения могут прерваться. Сеансы панели хранятся в памяти: после перезапуска
войдите снова с прежним паролем. Статус обновления переживает рестарт.

До остановки контроллера прочие изменения защищены блокировкой операций.
Процесс обновления отделён от контроллера и не завершается вместе с ним.
Неопознанный или погибший worker показывается как прерванное обновление.
Подробный журнал хранится локально рядом с config.json в `update.log`;
он не включается автоматически в диагностическую выгрузку. Не отключайте
питание при установке. При прерванной операции проверьте состояние службы и
резервную копию; отказоустойчивость при обесточивании не заявляется.

Проверки в среде разработки покрывают подписи, суммы, опасные архивы, отдельный
worker, сохранение конфигурации/пароля и завершение старого контроллера без
deadlock. Жизненный цикл настоящего установщика проверяется в отдельном
каталоге. Это не испытание обновления на KN-1811; его нужно подтвердить на устройстве.

API под обычной авторизацией и Origin: `GET /api/updates`,
`POST /api/updates/check`, `POST /api/updates/install` с полем `version`.
Метрики: `GET /api/device`. Температура читается только из Linux thermal/hwmon
в миллиградусах; при отсутствии датчика значение не придумывается. Процент CPU
и скорость WAN требуют двух последовательных замеров; обнуление счётчиков
или смена интерфейса сбрасывают вычисление скорости. Load average — отдельная
метрика очереди задач, а не процент CPU. Недоступные данные возвращаются null.
