# Keenetic Pilot для OpenWrt — отдельная экспериментальная платформа

**Стадия:** alpha.22 / проверка без OpenWrt-железа. Не выдавать эту ветку за
доказанно работающий обход. Все изменения выполнены в
feature/openwrt-support-alpha22; исходная сборка Keenetic с Entware
не меняет backend, сервис S98, NDM hook и iptables/PPE.

## Поддерживаемая системная основа

- OpenWrt **24.10** (opkg), **25.12** (apk), firewall4/nftables, procd.
  Старые сборки OpenWrt с firewall3/iptables пока не поддерживаются.
- ARMv7, ARM64, MIPS LE/BE, x86_64 **при совместимости штатного nfqws2
  с CPU и OpenWrt**. Не все маршрутизаторы и SoC гарантированно
  поддерживаются: проверка бинарника выполняется до установки.
- Требуются root, рабочий WAN-интерфейс, отдельная LAN-адресация и запас
  места в overlay/flash. Список пакетов: nftables, kmod-nft-queue, curl,
  ca-bundle, подходящие модули conntrack. Дополнительно может понадобиться
  ip-full (для корректного ip route get). На 24.10 устанавливайте пакеты
  opkg, на 25.12 — apk. **Установщик сам не меняет системные пакеты.**
- Нет зависимости от Entware на /opt, пакетов Keenetic NDM, legacy
  xtables-addons, proprietary PPE или встроенного C-ядра из MY.KN.
- Не поддерживаются автоматическая адаптация с CONNMARK и аппаратное
  ускорение PPE Keenetic. Состояние по умолчанию monitor-only.

## Платформенная архитектура

Движок Go и веб-панель общие. Для OpenWrt используется отдельный backend
в internal/pilot/openwrt.go, выбираемый исключительно явным
--mode openwrt (защита от случайного вызова Keenetic-режима на OpenWrt).

- Правила находятся **только** в собственной таблице
  inet keenetic_pilot. Таблица OpenWrt inet fw4 не удаляется и не
  перезагружается. Процессы/конфигурации других обходов не изменяются.
- Направление original на WAN ловится по oifname + tcp/udp dport,
  ответ reply по iifname + tcp/udp sport. Учитываются только первые
  20 пакетов в каждом направлении (при допустимом пассивном подборе 30).
  TCP по умолчанию, UDP только при явно включённом QUIC/Discord Voice.
  Используется NFQUEUE bypass: отсутствие слушателя не должно блокировать
  весь трафик.
- IPv6 по умолчанию выключен; включайте только после проверки маршрута
  и реального IPv6. Трафик с mark nfqws2 исключается из повторной очереди.
- Перед записью nft выполняется dry-run nft -c -f -, после чего
  запускается nfqws2 и только затем применяется отдельная таблица.
  При остановке таблица удаляется **до** остановки nfqws2.
  Чужая таблица с таким именем не перезаписывается. При аварийном
  завершении, если таблица осталась, ручная проверка обязательна;
  автоматического удаления неизвестных правил нет.
- При загрузке работает procd. Конфигурация/пароль в
  /etc/keenetic-pilot, приложение в /usr/lib/keenetic-pilot,
  временные данные в /tmp/keenetic-pilot-state, веб-панель на LAN:9080.
- Диагностика смотрит /overlay и потенциальные конфликтующие процессы.
  Не выключает аппаратный flow offload автоматически.

## Установка — экспериментальная

Пока не опубликован проверенный OpenWrt-выпуск, не используйте обычную
команду установщика Keenetic/Entware. Она предназначена ТОЛЬКО для Keenetic.

После загрузки совместимого tar.gz из независимого канала alpha.22
и проверки SHA-256 по опубликованному заранее значению:

1. Распакуйте архив в свободный каталог (обычно /tmp).
2. Запустите из него:
   sh keenetic-pilot/scripts/install-openwrt.sh
   Для ручного задания сетевых интерфейсов:
   sh keenetic-pilot/scripts/install-openwrt.sh --wan pppoe-wan --listen 192.168.1.1:9080
3. Установщик проверяет каждый файл, архитектуру, штатный бинарник nfqws2,
   Lua, OpenWrt и nft-синтаксис **до остановки старой службы**. Настройки
   уже установленной версии и пароль сохраняются, прежний бинарник
   резервируется.
4. Откройте локальную панель и убедитесь, что обход выключен. **Только
   после этого** можно включить его вручную и проверить связь, YouTube
   (не страницу, а видеопоток), Telegram TCP, CPU и нагрузку.
5. Если пропадает доступ, пользуйтесь консолью/SSH OpenWrt и
   /etc/init.d/keenetic-pilot stop. При штатной остановке Pilot удаляет
   только свою таблицу. Не применяйте fw4 flush или nft flush ruleset.

**Обновления OpenWrt из панели пока не включены.** Старые подписи и
процедуры установки из панели рассчитаны на /opt (Entware), поэтому
замена OpenWrt /usr/lib-пакетов через Keenetic-обновлятор намеренно
запрещена. Нужен отдельный проверенный worker с procd/rollback.
Вариант для OpenWrt не заменяет поддержку будущего ipk/apk-пакетирования.

## Техническая проверка

Сначала выполняется sh scripts/check.sh: Go unit/race тесты, shell syntax,
проверка nfqws2, Python-проверки архива и кросс-сборка пяти архитектур.
В аппаратном тесте обязательно проверять реальную nft syntax/kernel
extensions, совместимость бинарника и fw4 reload на конкретной модели.
Значения производительности, «работает YouTube/Telegram» и устойчивость
после перезагрузки **не объявлять подтверждёнными**, пока этого нет.

## Откат

- Остановить: /etc/init.d/keenetic-pilot stop.
- Полностью убрать только наш сервис и приложение:
  sh /usr/lib/keenetic-pilot/scripts/uninstall-openwrt.sh.
- Конфиг и пароль сохраняются, свои правила удаляются только при
  обнаружении собственного маркера. Неизвестные правила не затрагиваются.
- Для исключения риска сначала оставить второй путь доступа к роутеру
  (LAN/консоль); не включать перехват удалённо через единственный WAN.
